## What is actually true

`sessions.json` carries **twelve** readers, not eleven. The twelfth:

```
cli=claude-orphans   sessions=48   tokens=2,324,208,273
looked_in=['~/.claude.json', '~/.claude*/.claude.json']
```

Sessions whose **transcripts are gone**, recovered from the config's own
history. They are written into `sessions[]` tagged `cli: "claude"`, so:

```
claude reader (transcripts on disk) : 1,926,010,897   16,532 sessions
claude-orphans (transcripts gone)   : 2,324,208,273       48 sessions
                                      -------------   ------
sum of sessions[] where cli=claude  : 4,250,219,170   16,580 rows
totals.json grand_total             : 1,926,010,897
```

16,580 − 16,532 = **48**. The delta is **exactly** the orphans reader.

`analyze_tokens.py` reads transcripts, so it cannot see the 48. It is not
wrong; it is answering a narrower question. The gate compares the two as if
they answered the same one.

**The accurate Claude figure for this machine is 4,250,219,170**, and
`totals.json` — which the floor and several reports read — holds only
1,926,010,897. That is the one real defect below.

## FIXED — the orphans defect, and what it was really hiding

### F5. `sessions.py` now records WHICH READER produced each row
Every row is tagged `source`. Without it no consumer could tell a
transcript-backed session from an orphan recovered out of `.claude.json` —
both are written `cli="claude"`, and `transcript` is `False` on every row by
the time the file is read back.

### F6. The gate compares like-for-like
`check_consistency.py` subtracts each machine's `claude-orphans` reader total
before comparing against `analyze_tokens`. Read from the `readers` block, not
by filtering on `source`, so folders committed before today still check.
**Both `analyze_tokens == sessions` failures cleared — this machine's and
HP's.**

### F7. `fun_stats.py` no longer truncates the per-machine CLI table
The slice was `[:8]`. On `hp-laptop-linux` it silently dropped **copilot-chat
(1,214,160 over 11 sessions)** and **lmstudio (119,774 over 7)**. The gate
certifies every CLI against that table, so the truncation surfaced as
"copilot-chat is missing — not found" and was read as a fault in HP's *scan*
for six days. It was this renderer. A per-machine breakdown that omits a
machine's tools is the exact undercount this repository exists to catch.

### F8. Orphan-only accounts now reach the floor
`machine_floor` warned about accounts measured in `sessions[]` but absent from
`totals.json` and left them out — 523,372,063 under `broodierchip@gmail.com`
on this machine, in no row of any floor. An account measured ONLY as orphans
cannot be double-counted by folding it in: analyze_tokens reads transcripts,
an orphan has none, so it is absent by construction rather than by a naming
accident. The ambiguous case the warning exists for always has transcripts on
one side, so it never lands here and is still only reported.

### (was) 1. `totals.json` does not record the orphans, so the floor under-reports
The 48 orphan sessions are 2,324,208,273 real tokens with no transcript. They
exist in `sessions.json` and in `token_ledger.jsonl`. They do **not** exist in
`totals.json`, which is what `machine_floor`, `combine.py` and the README table
read. Every document sourced from `totals.json` is therefore short by the
orphans, and nothing says so.

This is the user's rule: *record the correct information, and make the
computation use the accurate information.*

**Fix (~30 lines, half a day):**
1. `analyze_tokens.py` writes an `orphans` block into `totals.json` —
   `{sessions, tokens, source: ".claude.json"}` — beside `grand_total_tokens`,
   which stays exactly what it is: transcripts on disk. Two named fields, never
   one blended number.
2. `machine_floor` adds the orphan tokens (they are already in the counter's
   window, so take `max`, not `+`, against the counter part — same rule the
   function already uses for `seen`).
3. `check_consistency.py:1348` compares
   `sum(sessions[]) − orphans == totals.grand_total`, and asserts the orphans
   figure matches the `claude-orphans` reader. The check then measures real
   drift instead of a reader it did not know about.
4. Add to `test_scanner.py`: a fixture with one orphan proves the gate passes
   *and* that deleting the orphan lowers no total.

## Design rules this is measured against

1. **Every machine writes its own files in its own folder.** Another computer's
   failure must never stop this one writing its record. `archive/` is the single
   deliberate exception — it snapshots every machine present.
2. **The floor is relative to the document.** Company document → floor per
   company; computer → per computer; account → per account. Once #1 lands,
   `machine_floor(slice)` is the shape this takes. A stats-cache has no
   per-model breakdown, so the counter's excess is apportioned by `by_model` or
   held as an explicit `unattributed` row — never credited silently to one
   vendor.
3. **A machine counts only its own profiles** unless told otherwise (#5).
