# Fix plan — 33 confirmed defects

From two adversarial sweeps on 2026-08-09 (34 agents, then 49). 40 candidates,
38 confirmed, 33 distinct after dedup. Every one was reproduced by an agent whose
job was to *refute* it.

**Ranked by (how silent × how reachable) ÷ fix size.** Not by severity alone — a
loud crash ranks below a quiet no-op, because the quiet one is what gets shipped
and believed.

**Status: 2 fixed, 31 open.**

---

## Group 1 — destroys data that already exists

### 1. `corpus_ship pack` masks a `tar` failure ⚠️ FIX FIRST
`corpus_ship.py:132`. A shell pipeline reports only the LAST command's status, so
`tar | zstd` returns zstd's. Reproduced:

```
shell returncode: 0        ← what the code checks
archive written:  1,760 bytes
members inside:   300 of 301
```

The sha256 is then taken **from the truncated file**, so `pull` verifies it and
`push --clobber` has already replaced the real offsite asset. Trigger is
ordinary — a transcript deleted mid-archive, which is exactly what retention and
Claude's cleanup do in bursts. Fires on Linux today.

**Fix (~20 lines):** two `Popen`s, check tar's status explicitly (`pipefail` is
not portable to `/bin/sh`), then count members in the finished archive against
the source folder and refuse to upload a short one.

## Group 2 — checks and suites that cannot fail

The class that matters most: these are read as evidence.

### 2. The retire exemption is permanently satisfied for every machine
`check_consistency.py`. `rm -rf` any machine → `PASS no machine folder has
disappeared`, exit 0, and `combine.py` renders the loss as "never scanned". My
own fix from earlier made the fatal branch unreachable.
**Fix (~15 lines):** keep the newest retire stamp per machine and compare against
that machine's last committed `totals.json`, not against "was it ever retired".

### 3. No suite ever executes a `sessions.py` reader — **largest hole in the repo**
Six planted breaks in `read_claude` (drop the streaming sum, drop either dedup,
first-profile-only, own-home glob, flat glob) all score **45/0**. `read_copilot →
return []` also scores 45/0. `update.py:192` runs `test_scanner.py` as a pre-scan
release gate whose own comment says it exists to catch a silently-wrong reader.
**Fix:** fixtures per reader, asserting a known total.

### 4. Subagent/workflow transcripts are unasserted — 18.23% of the tokens
4,224,787,878 of 23,177,513,548. Every fixture is depth-2, so a flat glob passes;
and **both scanners flatten identically**, so the `analyze_tokens == sessions`
cross-check stays green. Pinning the sessions.py side in the same fixture is the
load-bearing assertion.

### 5. `test_absent_is_not_zero` passes on an EMPTY reader registry
`set(READERS) - set(DETECT)` is `[]` when `READERS` is `{}`, and the per-reader
checks are *generated by iterating READERS* — so losing a reader **deletes
assertions instead of failing them**. Fix: symmetric difference plus a floor on
the count.

### 6. Cross-profile dedup on `message.id` is untested
The branch 100% of real rows take (2,498/2,498 sampled). Delete it and a copied
profile doubles; suite stays 45/0. The one cross-dir test uses `turn()`, which
emits no `message.id`.

### 7. `sessions.total()` has no assertion
Drop `cache_read_input_tokens` (95.23% of the fleet) → 45/0. `check_consistency`
catches it, but *after* the scan and after `token_ledger.record` has appended the
wrong figure under a new scanner rank, which then outranks the correct one.

### 8. `adversarial.py` grades `out.count("FAIL")` and discards `returncode`
The one signal `update.py` publishes on. A checker that prints FAIL and exits 0
gives a byte-identical verdict table. Fires at BASELINE, before any attack.

### 9. The flock attack is a timing race
~40% miss rate with the lock removed; detection tracks ambient load. Replace
with: hold the lock, assert `record()` blocks. 40/40 vs 0/40.

### 10. `adversarial_platform.as_platform()` never sets `os.name` or `which`
So both the Windows and macOS service-manager branches can only return `None` on
a Linux box, and both assertions accept `None`. Gutting either leaves 8/8 green.

### 11. The daemon suite's skip path is `check(name, True, True)` and drops 5 checks
While the summary still says 12 scenarios. **Armed today**: all five machines are
on a stale `scanner_version`, so one documented `run.py retire --yes` empties the
fleet and this becomes permanent.

### 12. `test_only_four_fields` asserts on the branch zero real records take
Caught on the `not mid` branch, missed on the `mid` branch.

## Group 3 — platform (macOS is live, Windows is preventive)

`macbook-air-m1` is scanned and in the fleet. `dell-latitude-7480-windows` is
registered and has never run.

### 13. `stores.py` pins the whole VS Code family to `.config/Code`
macOS uses `~/Library/Application Support/Code`. Two different failures:
**kilocode** is counted (the reader branches on darwin) and **never preserved**
(the archiver does not); **copilot-chat** is a silent **zero on both sides**.
Both designed alarms are blind — `unpreserved_readers()` returns `[]` because the
store IS in the list at an impossible path, and the NOT-COVERED loop does
`if not name.startswith(".")`, so `Library` is skipped before it is examined.
**Fix (~40 lines):** give `stores.py` the branch `sessions.vscode_roots()`
already has, in ONE place, and route the raw-`s.path` consumers through it.

### 14. `stores.resolve()` splits `"/"`-literals on `os.sep`
Native Windows: every globbed store → `[]`, while `exists()` and `detect()`
(glob-based) keep saying yes. Kills export of every non-default profile's
`.claude.json` — the orphan record. Worse than empty: a plain `~/projects` folder
resolves as a Claude store. **2 lines** — route `resolve()` through `glob.glob`.

### 15. One unreadable directory under `$HOME` kills the whole guard
`pathlib.is_dir()` re-raises `EACCES`. Loud under `--check`, **silent under
`--daemon`**: tick catches it, systemd shows active, `--verify-boot` passes
forever, archive never created. Trigger: one `chmod 700` project folder.

### 16. `os.walk(src)` with `onerror=None` returns `"ok"` for a subtree it never read
`(1, 0, 'ok')` with a locked subdir is indistinguishable from health. **2 lines.**

### 17. Root-file stores print `root files only` and drop the note
10 live stores; partial failure is byte-identical to success. **One line.**

### 18. `--apply` would rewrite a Windows-side `settings.json` through `/mnt/c`
Two vectors (symlink, `$CLAUDE_CONFIG_DIR`), unattended every 6h — and
`windows_side_profiles()` then re-reads the file the guard just wrote and prints
it as proof the Windows side was fine. Fix at `raise_period()`, not at
`find_config_dirs` — the counter must keep counting it.

### 19. WSL discovery uses the depth-1 name glob its own file calls defective
55 lines earlier. And prints nothing when it finds nothing (`if win:`), so "no
second install" and "40 transcripts at 30 days" emit identical bytes.

### 20. `find_config_dirs` dedups on `p.resolve()`
Reproduced on a real vfat mount. A phantom zero-token account inflates account
and session counts in every rollup. **The `st_ino == 0` fallback is mandatory**,
or network mounts collapse every profile into one key.

### 21. `sweep_usage.covered()` compares native-sep `rel` against `"/"`-literals
Windows only: 9 of 11 stores read as uncounted every run, burying the real
finding. Noise, not loss. The correct idiom already exists at
`retention_guard.py:567`.

### 22. A probe that could not run answers "no"
`_can_hardlink` converts every `OSError` to a definite `False`, so the
"UNVERIFIED is not the same as working" branch is dead; `_case_sensitive` returns
`None` on the identical condition and its warning is dropped. Two probes,
opposite directions, same wall.

### 23. The launchd install copies a plist that has never existed in this repo
Loud `cp` failure, lasting silence downstream: no daemon on a Mac.

### 24. `--verify-boot` rc=2 is reachable only on Linux-without-`/proc`
The exact inverse of all four places it is documented, and the
launchctl/schtasks remediation is stranded inside that dead branch — so a real
FAIL on macOS prints four systemd commands that do not exist there.

### 25. `schtasks ... ^` is CMD syntax printed to a shell labelled "powershell"
**One line** — delete the continuation character.
